# Errors and limits

Errors use a stable JSON shape:

```json
{
  "error": {
    "code": "invalid_subscription",
    "message": "Invalid option",
    "field": "period",
    "suggestedFix": "Use one of the supported billing periods: monthly, yearly, custom.",
    "allowedValues": ["monthly", "yearly", "custom"]
  },
  "requestId": "request-..."
}
```

`field`, `suggestedFix`, `allowedValues`, and `writableFields` are included when the server can provide a precise recovery hint. AI agents should use those fields to correct the payload instead of guessing.

## Common error codes

| Status | Code | Meaning |
| ---: | --- | --- |
| `400` | `invalid_json` | Request body is not a JSON object |
| `400` | `invalid_subscription` | Subscription fields failed validation |
| `400` | `invalid_subscription_field` | The request tried to write a server-managed field (such as `id` or `status`) |
| `400` | `invalid_subscription_id` | Subscription ID is not a valid UUID |
| `400` | `invalid_notification_settings` | Notification settings fields failed validation (e.g., `daysBefore` not in `1, 3, 7, 14`) |
| `400` | `invalid_notification_settings_field` | The request tried to write a web-only field (such as `barkUrl`, `timeZone`, or `locale`) |
| `400` | `invalid_pagination` | `limit` or `offset` query parameter is out of range |
| `400` | `invalid_query` | A filter or `sort` query parameter is invalid |
| `400` | `empty_patch` | `PATCH` body did not include any writable fields |
| `401` | `authentication_required` | Missing Bearer token |
| `401` | `invalid_api_key` | API key is invalid or revoked |
| `403` | `insufficient_scope` | The API key lacks the `write` scope required for this operation |
| `403` | `premium_required` | Endpoint requires Lifetime Premium (`duplicates` and `optimizations` analytics) |
| `404` | `subscription_not_found` | Subscription does not exist for the API key owner |
| `404` | `notification_settings_not_found` | Bark reminder settings have not been configured in the web app yet |
| `405` | `method_not_allowed` | HTTP method is not supported |
| `429` | `rate_limit_exceeded` | Per-minute user request quota or hourly failed-auth limit exceeded |
| `500` | `internal_error` | Unexpected server error |

## Recovery fields

| Field | Meaning |
| --- | --- |
| `field` | The request field that caused the error |
| `suggestedFix` | Human- and AI-readable correction guidance |
| `allowedValues` | Valid enum values for fields such as `currency`, `period`, or `daysBefore` |
| `writableFields` | Fields accepted by `POST` and `PATCH` requests on that resource |

Example non-writable field error on `/api/v1/subscriptions`:

```json
{
  "error": {
    "code": "invalid_subscription_field",
    "message": "Field is not writable: id",
    "field": "id",
    "suggestedFix": "Remove server-managed fields such as id, createdAt, and updatedAt before retrying.",
    "writableFields": [
      "amount",
      "billingAnchorDay",
      "category",
      "currency",
      "customDate",
      "isTrial",
      "lastPaymentDate",
      "name",
      "nextPaymentDate",
      "notificationEnabled",
      "period",
      "trialEndsOn"
    ]
  },
  "requestId": "request-..."
}
```

## Scopes and plan gating

- **Scopes**: A `read` key can list and read subscriptions, read notification settings, and call analytics and audit endpoints. A `write` key additionally allows create, update, delete, and notification settings updates. A write call made with a read-only key returns `403 insufficient_scope`; do not retry — request a write-scoped key. See [Authentication](/en/api/authentication#scopes).
- **Premium analytics**: `/api/v1/analytics/duplicates` and `/api/v1/analytics/optimizations` return `403 premium_required` on Free accounts. `/api/v1/analytics/summary` is available on all plans.

## Rate-limit headers

Authenticated `/api/v1/*` responses include:

```text
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 59
X-RateLimit-Reset: 1781568960
```

- Default authenticated quota: **60 requests per minute per account** (`API_RATE_LIMIT_PER_MINUTE`) on both Free and Premium plans.
- `X-RateLimit-Reset` is a Unix timestamp in seconds indicating when the current 1-minute window resets.
- Validation failures (`400`) on `POST`, `PATCH`, and query parameters are rejected **before** the per-minute quota is consumed, so they do not count against your limit and do not carry rate-limit headers. Fixing the payload and retrying is free.
- Every `429 rate_limit_exceeded` response (both per-minute user rate limits and hourly failed-auth lockouts) includes a `Retry-After` header with the number of seconds to wait before retrying:

```text
Retry-After: 45
```

## CORS

The public API supports browser preflight requests:

```text
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Authorization, Content-Type
Access-Control-Allow-Methods: GET, POST, PATCH, DELETE, OPTIONS
```

Keep API keys out of public browser apps unless you fully trust the browser context. CORS support is intended for developer tooling, internal dashboards, and trusted local workflows.
