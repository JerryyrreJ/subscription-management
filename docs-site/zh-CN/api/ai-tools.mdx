# AI 工具使用

首次接入请先阅读[连接 Agent](/zh-CN/user-guide/agent-setup)。在应用内 **设置 → API 与 MCP** 点击 **复制给 Agent**，即可生成包含当前站点地址、远程 Streamable HTTP MCP 端点（`/api/mcp`）、单文件本地 MCP 脚本（`/downloads/steadyrenew-mcp.mjs`）以及 API 契约链接的引导提示词。

如果你要直接接入自定义 Agent 框架，可使用 [AI tool schema](/api/ai-tools.json) 导入 JSON 工具定义，或使用 [OpenAPI schema](/api/openapi.yaml) 直接导入 OpenAPI。

## 推荐 Agent 策略

允许 AI 写入前，建议给助手配置以下规则：

```text
你可以直接查询订阅列表、支出汇总、通知设置和审计日志。
创建、更新、删除订阅或修改全局提醒设置前，必须先总结即将执行的变更并征得用户确认。
删除订阅前，必须重复订阅名称和 id，并说明删除仅移除本地追踪记录、不会替用户在服务商处退订。
不要发送服务端管理字段：id、status、createdAt、updatedAt。下次续费日期使用 nextPaymentDate。
如果 API 返回 field、suggestedFix、allowedValues 或 writableFields，使用这些提示修正 payload。
```

## 全部 11 个工具与选择指南

| 用户意图 | 工具 | Scope / 套餐 |
| --- | --- | --- |
| “显示我的订阅” / “最近两周哪些要续费？” | `list_subscriptions` | `read` |
| “查看这个订阅 UUID 的详情” | `get_subscription` | `read` |
| “添加 ChatGPT Plus” / “记一个 7 天 Figma 免费试用” | 确认后调用 `create_subscription` | `write` |
| “把 Netflix 改成年付” | `list_subscriptions`，确认目标和变更后调用 `update_subscription` | `write` |
| “删除重复的 Netflix 记录” | `list_subscriptions`，确认名称和 id 后调用 `delete_subscription` | `write` |
| “全局续费提醒开了吗？” | `get_notification_settings` | `read` |
| “提前 7 天提醒我续费” | 确认后调用 `update_notification_settings` | `write` |
| “我每个月各币种花多少钱？” | `get_spend_summary` | `read` |
| “帮我查查有没有重复订阅” | `find_duplicate_subscriptions` | `read`（Premium） |
| “有哪些月付订阅值得评估改年付？” | `get_optimization_suggestions` | `read`（Premium） |
| “刚才通过 API 改了什么？” | `list_audit_log` | `read` |
| “这是我的 Bark URL，帮我配置” | 拒绝；引导到网页端 **设置 → 通知** 与[续费提醒指南](/zh-CN/user-guide/reminders) | 仅网页端 |

## 风险等级

| 风险 | 工具 | Agent 行为 |
| --- | --- | --- |
| 低 | `list_subscriptions`、`get_subscription`、`get_notification_settings`、`get_spend_summary`、`find_duplicate_subscriptions`、`get_optimization_suggestions`、`list_audit_log` | 用户询问时可直接调用 |
| 中 | `create_subscription`、`update_subscription`、`update_notification_settings` | 调用前总结计划写入内容并请求确认 |
| 高 | `delete_subscription` | 调用前确认准确的订阅名称和 `id` |

公开 API 不支持通过 `status` 做软取消/暂停/恢复。如果用户说“取消订阅”，需要先确认：是删除 SteadyRenew 里的追踪记录，还是需要用户前往服务商官网取消真实扣款。

Bark URL、测试推送、`timeZone` 和 `locale` 不能通过公开 API 读写；请引导用户到网页端设置与[续费提醒指南](/zh-CN/user-guide/reminders)。

## 示例流程

用户：

```text
把 Netflix 改成年付。
```

助手：

1. 调用 `list_subscriptions`。
2. 找到 Netflix 记录。
3. 询问确认：

```text
我找到了 Netflix（33333333-3333-4333-8333-333333333333），当前为 monthly。我将把 period 改为 yearly，并保留当前的下次续费日期。确认执行吗？
```

4. 用户确认后，调用 `update_subscription`：

```json
{
  "id": "33333333-3333-4333-8333-333333333333",
  "patch": {
    "period": "yearly"
  }
}
```

## 错误恢复

错误响应使用稳定结构：

```json
{
  "error": {
    "code": "invalid_subscription",
    "message": "Invalid option",
    "field": "period",
    "suggestedFix": "Use one of the supported billing periods: monthly, yearly, custom.",
    "allowedValues": ["monthly", "yearly", "custom"]
  },
  "requestId": "request-..."
}
```

- **校验提示（`400`）**：根据 `field`、`suggestedFix`、`allowedValues` 和 `writableFields` 修正请求；若修正后的 payload 改变了实际写入效果，需重新向用户确认。
- **只读密钥（`403 insufficient_scope`）**：不要重试，提示用户改用具备 `write` 权限的 API Key。
- **高级版分析（`403 premium_required`）**：不要重复调用 `find_duplicate_subscriptions` 或 `get_optimization_suggestions`；说明这两项分析工具需要终身高级版（`https://steadyrenew.com/pricing`），或改用 `list_subscriptions` / `get_spend_summary` 完成基础汇总。
