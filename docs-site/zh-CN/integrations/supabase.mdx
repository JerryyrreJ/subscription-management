# Supabase 集成

Supabase 是 SteadyRenew 的可选云服务层。配置后可启用账号登录（邮箱密码、OAuth、Passkey 通行密钥）、多设备订阅与分类云同步、Bark 提醒配置、终身高级版权益状态、Developer API Key 以及 AI 录入月度配额与预算记账。

## 必需环境变量

```bash
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
SUPABASE_URL=
SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SECRET_KEY=
```

`SUPABASE_SECRET_KEY` 仅供 Netlify Functions 服务端使用（旧名 `SUPABASE_SERVICE_ROLE_KEY` 仍作为兼容别名支持）。

## 数据模型职责

- **用户档案（profiles）**：保存账户信息与终身高级版（Premium）权益状态。
- **订阅表（subscriptions）**：保存周期扣款、月付锚点日 `billing_anchor_day` 以及免费试用字段（`is_trial`、`trial_ends_on`）。
- **分类表（categories）**：保存用户自定义分类。
- **通知设置与发送锁**：保存 Bark 偏好、推送历史与防重锁。
- **API Key、限流窗口与审计日志**：仅存储 SHA-256 密钥哈希与 `scopes` 权限，记录每分钟请求限流、失败鉴权计数及公开 API 写操作快照。
- **AI 月度配额与预算窗口**：按用户记录**每月** AI 录入成功次数（Free `10` 次 / Premium `300` 次）及工作区级月度聚合 token 预留，不存储任何粘贴文本、截图或解析内容。
- **支付流水与账号注销**：用户通过 `delete-account.ts` 自助注销账号时，会彻底删除 Auth 用户及全部订阅、分类、API Key 数据；支付表中的 `user_id` 会置为 `NULL`，仅保留对账、退款和争议处理所必需的交易记录。

## Passkeys（WebAuthn 通行密钥）

通行密钥登录基于 Supabase Auth WebAuthn（客户端启用 `auth.experimental.passkey: true`，需 `@supabase/supabase-js` ≥ 2.105.0）。

### 本地 CLI 配置

`supabase/config.toml` 默认启用了：

```toml
[auth.passkey]
enabled = true

[auth.webauthn]
rp_display_name = "SteadyRenew"
rp_id = "127.0.0.1"
rp_origins = ["http://127.0.0.1:5173"]
```

本地测试通行密钥时请通过 `http://127.0.0.1:5173` 访问（优先使用 `127.0.0.1` 而非 `localhost`），使浏览器 Origin 与 `rp_id` / `rp_origins` 保持一致。

### 生产环境 Dashboard 配置

在 Supabase Dashboard 打开 **Authentication → Passkeys**：

1. 开启 Passkey 认证。
2. 设置 **Relying Party Display Name**（如 `SteadyRenew`）。
3. 将 **Relying Party ID** 设为主站裸域名（如 `steadyrenew.com`）。
4. 在 **Relying Party Origins** 中填入完整的 HTTPS 访问源（最多 5 个，如 `https://steadyrenew.com`）。
5. 确认 **Site URL** 与 **Redirect URLs** 包含 `/app` 回调地址，以保障 OAuth 与密码重置正常运作。

## 安全边界与域名迁移

- 对所有用户数据表保持启用 Row Level Security（RLS）。
- 绝不能将 `SUPABASE_SECRET_KEY` / `SUPABASE_SERVICE_ROLE_KEY` 放入前端 `VITE_*` 变量。
- 通行密钥与注册时的 Relying Party（`rp_id`）域名强绑定，无法通过修改回调地址跨域名迁移；更换主域名后，老用户需先用邮箱密码或 OAuth 登录新域名，再重新注册新的通行密钥。
